# AI优化图到AI生成视频玩法产线设计

日期：2026-06-10

## 背景

现有 `2026-05-29-horizontal-v7` 保姆级教程链路已经承担“客户跟着点、知道怎么操作”的职责。用户现在要借鉴“computer use 自动跑录屏 + 采集系统 + 模板化包装”的新方法，但不替换原有教程线。

新方法只服务“客户玩法案例视频”：把多个功能点组合成一个电商打法，展示老商品图先被 AI 优化，再确认发布到商品，最后用 AI 批量生成视频做成可投放/社群展示的商品视频。

## 决策

采用双轨模式：

- 单功能教学视频继续用老办法：真实网页操作、审片台逐镜批改、按审片台出片。
- 功能组合玩法视频使用新方法：先采集真实链路素材，再进入素材库和玩法模板，最后生成客户版玩法视频。

第一条玩法只做一个闭环：

```text
老商品图/老商品信息
→ AI优化商品图
→ 查看优化结果
→ 确认发布到道理门测试店商品
→ 进入 AI视频 > AI生成视频
→ 选择平台、店铺和商品
→ AI批量生成视频
→ 查看生成记录/视频结果
```

## 目标用户和话术定位

视频给客户看，不是给内部拍摄或开发人员看。口播要围绕电商经营结果：

- 主图和卖点图负责提升点击率。
- SKU图和清晰规格负责减少犹豫，提高转化。
- AI商品视频负责提升停留、互动和商品理解。
- 一套流程从老商品素材开始，不要求商家先找设计师逐张修图。

口播不能出现“这一镜要拍”“给客户看清楚”“素材采集失败”等内部制作话。

## 非目标

- 不改动现有 `2026-05-29-horizontal-v7` 审片台和保姆教程正式出片链路。
- 不在第一版做短视频干货风、竖屏版或多套模板。
- 不把 AI生成视频功能硬写成已知路径；如果路径或控件未确认，采集阶段必须停下来标记“需要实测”，不能用假画面补。
- 不自动充值。
- 不在非测试店发布。

## 架构

### 1. 真实链路采集层

职责：用 Chrome 登录态和 computer use 采集一条真实流程。

输入：

- 测试店：道理门。
- 目标流程：AI优化商品图确认发布后，再用 AI生成视频生成。
- 允许动作：在测试店真实确认发布、真实生成视频。

输出：

- 屏幕录制。
- 关键截图。
- 页面 URL 和步骤状态。
- 生成记录或失败原因。

采集策略：

- 优先真实操作，不靠凭空合成页面。
- 能自动点的步骤自动点；路径不确定时人工接管确认。
- 每个关键状态都要保存截图：功能入口、平台下拉、店铺选择、商品列表、优化结果、确认发布、AI视频入口、立即生成、生成记录。

### 2. 素材采集和标签层

职责：把录屏和截图整理成可复用素材库。

每个素材记录为一个 manifest 条目：

- `id`：稳定素材 ID。
- `type`：`operation-screenshot`、`dropdown-open`、`before-after`、`generated-image`、`publish-confirm`、`video-result`。
- `sourcePath`：本地文件路径。
- `featureTags`：如 `ai-image-optimize`、`selling-point`、`sku`、`brand-display`、`confirm-publish`、`ai-video`。
- `store`：道理门。
- `platform`：如抖音。
- `createdAt`：绝对时间。
- `notes`：可选人工说明。

第一版不要求 OpenCV 全自动识别所有区域；可以先以截图和人工确认标签为准。后续再增加自动切关键帧、自动识别红框区域、自动筛掉无效帧。

### 3. 玩法模板层

职责：把素材组合成客户能看懂的玩法视频。

第一版模板结构：

1. 痛点：老商品图点击弱、素材不统一。
2. 第一步：AI优化商品图生成新主图/卖点图/SKU图。
3. 第二步：确认发布，把优化图写回商品。
4. 第三步：AI生成视频读取发布后的商品图。
5. 结果：主图拉点击，视频拉停留和转化。

模板字段：

- `title`：玩法标题。
- `hook`：开头 3-5 秒。
- `scenes`：镜头列表。
- `requiredAssets`：每镜需要的素材类型。
- `copyTone`：客户版、短句、结果导向。
- `cta`：让客户知道可以按这套流程处理自己的商品。

### 4. 玩法视频审片层

职责：给用户批改玩法视频，而不是逐按钮教学。

审片项：

- 玩法标题。
- 每镜是否保留。
- 素材选择和替换。
- 镜头顺序。
- 字幕位置。
- 口播和屏幕文字。
- 是否使用 AI生成视频结果片段。

审片台必须能删除镜头，删除后出片跳过；必须能替换素材，替换后出片使用新素材。第一版可以复用老审片台的思想，但数据和输出目录必须独立，避免污染老教程线。

### 5. 渲染层

职责：按玩法模板和审片结果输出横版客户玩法视频。

第一版只输出：

- 横版 MP4。
- SRT 字幕。
- 玩法脚本 Markdown。
- 素材 manifest。
- 构建报告。

口播要求：

- `SKU` 配音读作 `S K U`。
- `AI` 配音读作 `A I`。
- 音画总时长必须一致，保留真实静音。

## 数据流

```text
Chrome真实操作/Computer Use
→ 录屏 + 截图
→ 素材 manifest
→ 玩法模板 recipe
→ 玩法审片台
→ browser layout / review overrides
→ 横版玩法视频 + 字幕 + 报告
```

## 第一版验收标准

- 老 `2026-05-29-horizontal-v7` 成片和审片台不被修改。
- 有一条道理门测试店真实链路素材。
- 素材 manifest 至少包含：AI优化结果、确认发布、AI视频生成入口、生成记录或视频结果。
- 生成一个横版客户玩法视频。
- 视频内容明确表达“先优化图，再确认发布，再 AI 批量生成视频”。
- 口播面向客户，不出现内部制作话。
- 成片可直接打开，字幕与口播一致。
- 如果 AI生成视频路径或结果页没跑通，报告必须写明卡点，不能用假结果补成闭环。

## 风险和处理

- 页面路径不确定：采集层停在当前页面，保存截图和 URL，等待人工确认，不编造步骤。
- 生成等待时间长：报告记录等待时长，成片只展示关键状态，不把长等待直接塞进视频。
- 发布失败：保留失败截图，玩法视频不进入最终渲染，报告标记失败。
- 多标签页干扰：采集脚本优先选择当前 Chrome 活动页，并记录目标 URL。
- 素材太丑：素材库允许人工标记 `reject`，模板不使用被拒素材。
